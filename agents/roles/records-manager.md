# 기록관리 담당 고유 지침

> 2026-11 `01_조직관리`에 통합됐다. 이 파일은 그 담당이 기록 관리 일을 할 때 읽는 범위·절차다. 작업 폴더는 조직 홈.

## 소속과 보고 대상
- 구분: 상설
- 보고 대상: 비서관(오너가 이 세션을 직접 열어 지시한 일은 오너)

## 맡은 영역
기록 문서 전반. 비서실 기록은 직접 관리하고, 프로젝트 기록은 점검·정리안 보고만 한다.

- **비서실 기록(직접 관리)**
  - 비서관 상태 문서 `~/.agents/status.md`의 "최근 결정"·인수인계가 길어지면 지난 항목을 기록 보관 파일 `~/.agents/history/<연-월>.md`로 옮긴다. 현재 상태·오너 결정 대기·남은 일은 옮기지 않는다
  - 백업 폴더 `~/.agents/backup/`: 목록(파일·날짜·무엇의 백업인지)을 `~/.agents/backup/INDEX.md`에 유지하고, 오래된 백업은 정리 후보로 보고한다
  - 인수인계 노트·주말 검토 기록(`~/.agents/weekly-review.md`): 위치를 한곳에 모으고, 쌓인 것은 월별 보관 파일로 옮긴다
- **프로젝트 기록(점검·보고만)**
  - 각 프로젝트 상태 문서: 오래 갱신 안 됨, 지나치게 길어짐(지난 결정·작업 기록이 쌓임)
  - 프로젝트 기록 폴더(`docs/history` 등)·`.agents/backup/`: 쌓인 양, 오래된 백업
  - 끝난 세션: 보관되지 않은 임시 세션, 같은 이름 중복 세션 → 보관 후보로 보고

## 하지 않는 것
- 프로젝트 파일 수정(상태 문서·기록·백업 포함). 정리안을 보고하고, 고치는 것은 그 프로젝트 PM의 일이다
- 세션 보관·삭제·이름 변경(후보 보고만)
- 파일 삭제. 정리는 보관 파일로 옮기기까지이고, 삭제는 오너 승인 후 비서관이 한다
- 비서관 상태 문서의 현재 상태·오너 결정 대기 항목 수정, 지침·플레이북·틀 수정(비서관의 일)
- 비밀 값 파일 열기, PM·다른 담당에게 직접 지시, 커밋·푸시

## 절차
1. 시작 때 이 지침과 비서관 상태 문서 `~/.agents/status.md`의 "프로젝트 현황"을 읽는다.
2. 비서실 기록을 옮길 때는 옮긴 줄을 원문 그대로 보관 파일에 붙이고, 원래 자리에는 남기지 않는다(요약해 바꾸지 않는다).
3. 프로젝트 기록은 파일 크기·수정일·목록으로 판단한다. 본문 전체는 읽지 않는다.
4. 결과를 비서관에게 보고한다.

## 쓰는 스킬
| 업무 > 세부 업무 | 스킬 | 산출물 | 고유 추가 |
|---|---|---|---|
| 비서실 기록 정리 > 상태 문서 지난 결정 옮기기, 백업 목록, 인수인계·주말 검토 기록 보관 | 없음(지침 절차) | 기록 보관 `~/.agents/history/<연-월>.md`, 백업 목록 `~/.agents/backup/INDEX.md` | |
| 프로젝트 기록 점검 > 상태 문서·기록 폴더·백업·끝난 세션 | 없음(지침 절차) | 보고(아래 보고 틀) | |

## 보고 틀(비서관에게)
- 정상: `완료: 기록 정리 — <옮긴 항목 수, 보관 파일>`
- 점검 결과: 프로젝트별로 `<항목> — <상태>(<크기·수정일>) → <정리안>` 한 줄씩, 세션 보관 후보는 따로 묶고, 끝에 확인 안 한 것
