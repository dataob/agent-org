# 조직도 작성·갱신

## 산출물
- 이름·위치: 조직도 `~/.agents/org-chart.md` (프로젝트 폴더가 아니라 홈 개인 기록)
- 관리 주체: `01_조직관리`. 비서관은 직접 쓰지 않고 갱신을 요청한다
- 형식: 프로젝트(H2) > 담당(H3) > `역할: 구분(지침: 경로)` / `업무(스킬: 이름 → 산출물: 이름)` > 세부 업무. 고유 추가가 있으면 세부 업무 아래 `고유 추가: ...`
- 필수 내용: 맨 위 확인일과 관리 담당, 프로젝트 요약 표, 프로젝트마다 PM·담당, 어긋남 절
- 갱신 시점: PM의 재구성 알림(플레이북 8-1 7단계), 채용·정리 소식, 주말 정례 검토
- 완료 기준: 확인일 갱신, 바뀐 프로젝트·담당이 반영됨, 확인 못 한 것은 "확인 안 함"으로 표시

## 원천(읽기만)
1. 각 프로젝트 `AGENTS.md` 명단, `.agents/roles/<담당>.md`의 "쓰는 스킬" 표
2. 세션 목록(세션 목록 도구, 보관 포함)
3. 비서관 상태 문서 `~/.agents/status.md`(처음 만들 때만)

## 절차
1. 바뀐 프로젝트의 명단과 지침 표를 읽는다(전체 본문은 읽지 않는다)
2. 담당마다: 세션 이름, 구분(상설/임시/휴면), 지침 경로, 업무(스킬 1개, 산출물), 세부 업무를 지침 표 그대로 옮긴다
3. 지침에 없는 것을 추정해 채우지 않는다. 없으면 "없음", 확인 못 했으면 "확인 안 함"
4. 어긋남 절을 `org-chart-audit` 결과로 갱신한다
5. 확인일을 고치고 바뀐 줄만 비서관에게 보고한다

## 하지 않는 것
프로젝트 파일·지침·명단 수정, 세션 이름 변경·보관, PM·다른 담당에 직접 지시, 커밋·푸시. 어긋난 것은 보고만 한다.

## 규칙(오너 11-22)
- 담당 1명 = 지침 1개, 업무 1개 = 스킬 1개, 스킬 수행 결과가 산출물
- 스킬은 3단계 상속: 담당 → 프로젝트(PM 관리) → 전역(비서실 관리)
- 지침도 전역 → 프로젝트 → 담당으로 상속, 충돌하면 아래(구체적) 지침을 따르되 위 단계의 금지·승인 규칙은 낮추지 못한다
