# 운영 세부 규칙

> 전역 지침에서 떼어 낸 세부 규칙이다. 전역 지침의 해당 줄이 가리킬 때, 그 일을 할 때만 읽는다.

## 1. Claude·Codex 공용 원본 (파일·스킬을 만들 때)
- 프로젝트 지침 원본은 `AGENTS.md`이고, Claude용 `CLAUDE.md`는 `@AGENTS.md` 한 줄이다.
- 스킬 원본은 `.agents/skills/`이고, `.claude/skills/`는 그 폴더로 연결된 링크다. 새 스킬은 `.agents/skills/`에만 만들고 사본을 따로 두지 않는다.

## 2. 작업 환경 (실행 시각·상시 가동·재부팅·자원이 걸린 일)
- 이 컴퓨터의 상시 가동·잠자기·재부팅 동작·예약 작업·도구는 `~/.agents/environment.md`(환경마다 로컬, 비서관 관리)에 있다.
- 프로젝트 전용 예약 작업·서비스는 그 프로젝트 PM이 프로젝트 문서(`AGENTS.md` 또는 상태 문서)에 시각·필요 조건·해제 방법을 적어 관리하고, 비서관에게 알리지 않는다. 작업 환경 문서에는 작업 이름과 프로젝트만 두고, 비서관이 주말 정례 검토 때 실제 목록과 맞춘다.
- 새 예약 작업은 다른 작업과 시각이 겹치지 않게 `~/Library/LaunchAgents`의 기존 작업을 보고 정한다.
- 여러 프로젝트가 함께 쓰는 것(전원·잠자기, 원격 접속, 공용 도구·서비스, 컨테이너 도구)이 바뀌면 바꾼 에이전트가 PM을 거쳐 비서관에게 알리고, 비서관이 작업 환경 문서를 갱신한다.

## 3. 일반 지침·스킬 모으기
- 업무 중 다른 프로젝트에서도 쓸 만한 지침·틀·스킬이 생기면 PM이 비서관에게 알린다.
- 비서관이 일반화해 `~/agent-org`(전역 원본 저장소, 홈의 전역 파일은 여기로 가는 링크)에 반영한다(오너 확인 후).

## 4. 단어사전
- 공통 용어: `~/.agents/glossary.md`(비서관 관리)
- 오너 줄임말: `~/.agents/glossary-local.md`(비서관 관리, git 제외)
- 프로젝트 용어: 그 프로젝트의 `.agents/glossary.md`(PM 관리)
- 시작 때나 낯선 말·오너의 줄임말이 나왔을 때만 읽는다. 새 용어가 생기면 그 사전에 추가하고, 겹치면 프로젝트 사전이 우선한다.

## 5. 세션 정리 세부
- 언제: 작업 묶음이 끝났을 때, 대화가 자동 압축됐을 때, "[세션 정리 알림]"을 받았을 때.
- 순서: 하던 작업 단위를 마친다 → 상태 문서를 갱신하고 인수인계 요약을 남긴다 → 오너에게 한 줄로 알린다 → 같은 세션을 비운다. 새 세션은 만들지 않는다(세션 목록 유지).
- 비우는 방법: Claude Code 에이전트는 앱의 세션 비우기 기능(`clear_session`, 대상 "self")으로 스스로 비운다. 막히면(Remote Control 켜짐, 승인 거부 등) 오너에게 그 세션 입력창에서 `/clear`를 안내한다. Codex는 오너에게 안내한다. 대화 원본은 남는다(되돌리기: "Resume previous session").
- Remote Control: 켜진 세션은 비우면 원격 연결이 꺼진다. 비운 직후 다시 켠다(에이전트가 앱의 Remote Control 켜기 기능으로, 안 되면 오너가 그 세션 도구 막대에서). 비우기 전에 켜져 있었는지 상태 문서 인수인계에 적어 둔다.
- 비운 직후: 고유 지침과 상태 문서를 먼저 읽는다. 오너의 첫 말이 인사여도 짧은 업무 브리핑(현재 상태, 결정·확인할 것, 다음 할 일 제안)으로 이어간다.
- 훅: Claude Code에서는 `~/.agents/hooks/session-tidy.sh`가 대화 기록 2.5MB마다·자동 압축 직후에 정리 알림을, 새 세션을 연 직후와 비운 직후에 읽기 안내를 넣는다. Codex는 이 규칙만 따른다.
